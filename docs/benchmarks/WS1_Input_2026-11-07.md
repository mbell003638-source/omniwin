# WS1 desktop input benchmark — 2026-11-07

Historical Debug baseline. The subsequent [functional acceptance record](../status/WS1_Acceptance_2026-11-07.md) supersedes the everyday-task status below. These measurements used the DLL-hosted test runner; use the manifest-aware test EXE for subsequent physical-input runs.

The repeated-input benchmark passes functionally, but action prechecks and physical click dispatch exceed the contract budgets. The earlier two-click sample is superseded by 200 measured clicks in each of two runs. Everyday acceptance tasks were not attempted.

## Method

- Debug build on this PC, Windows build 26300, .NET 10.0.14, Smart App Control off.
- Direct `DesktopEngine` calls to the owned WinForms fixture. MCP transport overhead is not included.
- Production `SafetyGate`, stop hotkey, and keyboard/mouse activity hooks enabled. Real user activity aborts subsequent shared-input actions; cooldown is 500 ms.
- Each run has 10 warmup cycles followed by 200 measured cycles. Each cycle performs one physical Apply click, editor focus setup, Ctrl+A, and a 23-UTF-16-unit Unicode insertion with two independently focus-checked input batches.
- Every click must report the physical channel and increment the fixture counter by exactly one. Every insertion must report confirmed and read back the exact expected value. The Delete counter stays zero.
- Action summaries exclude warmups. Percentiles use nearest rank. Raw samples include phase timings, statuses, and channels. Each report has `Failure=null` and 200 measured samples for every operation; both test summaries report zero failures.
- `checks` is resolve plus precheck, including fresh rechecks inside dispatch. Gate, native/provider dispatch, and verification are separate. Percentiles of separate phases cannot be added to derive a total percentile.

## Next profiling work

Click dispatch timing surrounds `SendInput` itself. Its approximately 31 ms p95 is independent of UIA prechecks. External input hooks and scheduling are possibilities; these measurements do not identify the cause. OmniWin's production hooks remained enabled in both runs.

Before changing the checks, add separate in-memory timings for:

- `ReadLive` and `HitTest`: each physical click currently performs two fresh live-target traversals and three UIA point tests.
- `CaptureTypingExpectation`: the native Edit path still performs several password/value/provider reads plus two selection messages.
- `FocusForTyping`, each `RequireKeyboardFocus`, and `CheckInputBoundary`: two-batch typing performs repeated fresh focus and desktop/window checks.

Keep nested diagnostic measurements separate from aggregate phase totals. Preserve all fresh identity, focus, occlusion, stop/activity, and policy checks while measuring. Broader WPF/Chromium, large document, multi-monitor, cold-session, and real workflow acceptance remain open.

## Reproduce

Build the solution first. On an unlocked idle desktop, run from the repository root:

```powershell
$env:OMNIWIN_UI_BENCHMARK = '1'
$env:OMNIWIN_BENCHMARK_OUTPUT = Join-Path (Get-Location) ('artifacts\benchmarks\desktop-' + [guid]::NewGuid().ToString('N') + '.json')
try {
    & '.\tests\OmniWin.Desktop.Tests\bin\Debug\net10.0-windows10.0.19041.0\OmniWin.Desktop.Tests.exe' -class OmniWin.Desktop.Tests.DesktopBenchmarkTests -noColor -noLogo -showLiveOutput
    $report = Get-Content -LiteralPath $env:OMNIWIN_BENCHMARK_OUTPUT -Raw -ErrorAction Stop | ConvertFrom-Json
    if ($null -ne $report.Failure) { throw $report.Failure }
    foreach ($operation in @('click', 'type', 'keys', 'focus_setup')) {
        if ($report.Summaries."$operation.total".Count -ne 200) { throw "Incomplete $operation samples" }
    }
} finally {
    Remove-Item Env:OMNIWIN_UI_BENCHMARK, Env:OMNIWIN_BENCHMARK_OUTPUT -ErrorAction SilentlyContinue
}
```

Inspect the test summary as well as the report: the direct xUnit executable returned process exit code zero even for an earlier preflight assertion failure. A missing report, non-null failure, incomplete sample count, or failed test summary invalidates that run.
